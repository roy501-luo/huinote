# 开发与打包

使用 Swift Package Manager，系统框架和系统 SQLite，无第三方 Swift 包。`Package.swift` 声明 macOS 14、Swift 6 工具链，业务源码按 Swift 5 语言模式编译。

```sh
./scripts/verify.sh
./scripts/build.sh
open "dist/HuiNote · 会记.app"
```

`build.sh` 先校验并复用固定钥匙串组件，编译主程序，在临时目录组装并验证签名，最后复制到 `dist/HuiNote · 会记.app`。默认使用 debug 构建；`MEETING_BUILD_CONFIGURATION=release` 使用优化构建，尚未提供公证发行流程。完整 Xcode 可运行 `swift test`；仅有 Command Line Tools 时优先使用验证脚本。

环境变量：

- `MEETING_SIGN_IDENTITY`：固定证书的 40 位 SHA-1 指纹，优先于本地 `signing/identity.txt`。
- `MEETING_APP_OUTPUT`：构建输出路径；日用更新不要随意变更路径。
- `ALLOW_ADHOC_SIGNING=1`：仅用于隔离编译检查。临时签名不满足钥匙串组件的固定证书要求，不能作为完整功能验收版本，也不要覆盖日用 App。

不同电脑首次编译会将新证书指纹写入忽略的生成源码并构建对应 helper；不会提交本地证书。已有同源同身份的 helper 缓存保持不变。签名校验失败时先检查证书、钥匙串锁定及构建环境访问权限，不要通过清空系统隐私授权解决。

## 提交范围

只提交源码、资源、测试代码、脚本和通用文档。`.gitignore` 排除构建产物、证书配置、helper 缓存、个人验收数据和本地历史记录。不要使用 `git add -f` 绕过这些规则。

打包源码：

```sh
git archive --format=zip --prefix=meeting-assistant-macos/ -o dist/meeting-assistant-macos-source.zip HEAD
```

源码 ZIP 不包含签名身份、Key、会议库或可运行二进制。当前公开测试包使用固定本机签名，尚未 Apple 公证；首次打开按安装指南操作。目前没有设置自动发布或自动更新。

## Beta 发布包

运行 `./scripts/package-beta.sh` 生成独立优化构建的 ZIP 和 SHA-256 校验文件，不替换日用 App。版本发布使用 Git 标签及 GitHub Pre-release；包内只有签名 App 和通用安装文档。发布前核验源码提交、架构、签名、解包和排除敏感数据。

图标由 `scripts/generate-icon.swift` 以矢量绘制，可生成 16–1024 px 图标集；执行 `iconutil -c icns .build/HuiNote.iconset -o Resources/HuiNote.icns` 打包。应用显示名称为 HuiNote · 会记，Bundle ID、Keychain 服务与数据目录保持兼容。

## 自定义本地资料目录
设置 → 本地资料目录 → 选择目录并迁移资料。仅接受资料库之外的空文件夹；录音、数据库、Plaud 原件和批量任务状态一起复制并校验，成功后切换路径，旧目录保留备份。录音、同步、问答或批量任务运行期间不可迁移。自定义磁盘不可用时明确报错，不创建空资料库。密钥仍在 Keychain。

新导入的 Plaud 资料复制到资料库内的 `PlaudArchive`，不再直接依赖导入源目录。历史原件迁移应逐文件校验，并保留重新识别前的原稿；同步工具的浏览器登录目录也必须保留。

## 同步与媒体导入
侧栏“同步 Plaud”直接读取本地待导入资料并从云端下载新录音；文件编号去重。列表或下载遇到认证失效时打开原工具的登录窗口，完成后自动重试一次。网络错误不冒充登录失效，取消登录保留已完成下载。
设置内提供本地纪要目录选择、本地纪要导入，以及音频/视频录像导入。媒体导入使用 AVFoundation 提取 M4A 音轨，并把原文件和音轨一起保存到资料库；随后从会议总结页生成转写和纪要。无音轨文件明确报错。`python3 Verification/VerifyPlaudBridge.py` 可离线验证登录恢复，`VERIFY_MEDIA_VIDEO=/path/to/2-second-test.mp4 ./scripts/verify.sh` 可补测视频导入。

### 会议检索词
- 文件夹用于手动归类，检索词用于跨文件夹检索；二者共存。侧栏仅保留导航，会议列表与详情位于主区域，返回保留筛选和阅读位置。
- `MeetingKeyword` 分类：人、时间、地点、项目、组织／学校、主题、自定义。单场/批量总结响应一起提取；页面保留编辑用于调整，不再单独发起提取请求。
- 自动词必须出现在本段原文，去重且限制长度；不推断人物身份或别名。长会议逐段提取。用户可增删，手动词重新生成总结时保留。
- 会议 JSON 新字段均可缺省，FTS 索引版本 5 增加 keywords 文档。短词也沿用现有检索；点击标签搜索相关会议，匹配结果定位总结页。
- 一次性读取旧 folders.json，将原文件夹名转成手动“自定义”词，然后把旧映射归档到 maintenance-backups；迁移可重入，保留原资料。

### 会议交互与暂停
- 暂停保持当前会议锁定，停止双路采集并finish ASR；恢复创建新连接、按已录时长设置origin，AudioWriter载入segments.json并续增文件序号，避免覆盖。每段任务统计按音源+taskID保留。
- 转写页下方笔记仍使用原notes字段与自动保存，不改变纪要和问答的取证数据来源。

### 自动网络恢复
`LiveASRSession`按音源管理连接和有界队列，`LiveAudioRoute`让采集回调只做短锁及非阻塞入队。初次启动允许缓冲，重连只路由连接成功后的音频；每次用新taskID、沿用录音时间偏移。停止会先关闭入口并取消退避，避免暂停后继续重连。永久错误不得重试。
会议`automaticRepair/repairAfter/repairAttempts`兼容旧数据，可跨重启恢复会后补齐。处理成功先保存最终句子再清除标记；网络错误退避，用户取消清除自动执行标记。任务仅在App运行且空闲时执行，不创建系统定时任务。
隔离验证：`Verification/VerifyLiveASR.swift`。开发故障注入：随`--verify-asr-file <本机测试音频>`加`--verify-recovery`，在第4秒主动断开system一路并触发真实会后补齐；会使用已保存Key，创建明确标记的验证会议，不录制环境声音。

### 实际传输故障回归
`Verification/network_proxy.py <控制文件> <端口>` 提供仅监听127.0.0.1的透明CONNECT转发，只允许百炼相关aliyuncs域名443端口，不终止TLS、不记录请求内容。控制文件写入`offline`会关闭现有隧道并拒绝新连接；写入`online`恢复。
仅显式使用`--verify-network --verify-network-proxy-port <端口>`启动时，测试进程的实时和会后URLSession才使用该转发，可配合`--verify-asr-file <音频路径>`。结束测试须退出测试进程、关闭转发，再无参数启动App；不修改用户网络或持久设置。
2026-10-13此测试覆盖真实POSIX断线错误，发现并修复仅识别URLError的重连遗漏。验收应同时比对原始/双路解码采样、最终全文、持久化补齐状态，并在会后处理完成后用CPU时间增量测空闲资源；不要用进程生命周期平均CPU或主动调用fail替代这些证据。

### 2026-10-14 交互与数据兼容
- `Meeting.preferredMinutesTemplate` 为可选模板快照；本场选择不写全局默认，旧资料继续兼容。模板编辑器的`selectAsDefault`区分设置与本场路径。
- `FinalSentence.originalText` 在首次校对时保留原始识别，多次修改不覆盖它；句子ID和时间点不变。保存使用Store更新索引，既有evidenceBasis/digest提示旧总结和问答过期。
- TranscriptReview集中本场搜索、发言人筛选和校对编辑；引用跳转清除筛选，避免目标句被隐藏。
- BackgroundTaskView只呈现既有队列和恢复动作，不改变任务持久化机制。设置分组不改偏好键名或钥匙串服务名。

### 本场问答与发言人归纳（2026-10-14）

- 问答请求携带发言人名称、时间点和原文；请求内使用短编号，返回后映射到原有稳定证据 ID。音源标签不作为真实身份。
- 支持有据的观点归纳，每个要点必须关联本场原文。模型摘录逐字校验；要点引用了合法句子但摘录清单遗漏时，附上本地原句。未知 ID、空引用或不完整输出不会作为有效答案保存。
- 小于 24000 字符预算（含来源开销）的会议一次读取完整上下文；更长资料分段找证据后汇总，超限明确提示，不静默裁剪。
- `QAEntry.points` 为可选字段，兼容旧摘录式问答。历史问答与原文快照保留；答案为模型归纳，引用存在性校验不等于语义正确性证明，仍可点击核对。
- 问答界面独立在 `MeetingQAView.swift`。回车换行、Command-Return 发送；失败原位重试，成功回答的原文摘录可展开。每次提问独立检索，不隐式引用前次 AI 答案。
- 回答生成后另做一次原文审校，去除超出引用的推断；短会议为完整原文生成加候选观点审校两次调用。无依据问题可在首轮直接拒答。
- 问答滚动使用普通 VStack 与原生 `defaultScrollAnchor(.bottom)`，避免 macOS 上动态长答案与命令式滚动组合引发的布局循环。

### 发言人核对与总结前置流程（2026-10-15）
- 手动总结入口统一调用 `requestSummary()`：已有最终稿先切换至转写页的独立 `SpeakerSidebar`；无最终稿时使用 `reviewBeforeSummary` 完成识别后保存并返回，不立即调用 LLM。选择“稍后生成”可稍后继续，原有总结保留。
- 右侧维护区域提供编号、可编辑姓名/身份、发言句数、筛选及代表句试听；左侧保留完整转写。不同发言人使用稳定颜色区分。姓名使用现有本场 speakerNames 持久化；总结和问答证据继续通过原有姓名映射读取。
- 总结正文顶部 `SpeakerReviewSection` 提供常驻姓名概览与维护入口；转写筛选旁也可展开或收起同一侧栏。试听清除正文筛选，避免目标句被隐藏；播放可随时暂停。
- 自动会后处理和批量任务仍沿用原流程，不增加交互阻塞。新一次说话人聚类不继承旧编号身份，不提供跨会议声纹识别。

- 检索词不再提供独立生成按钮或单独网络任务；随单场/批量总结自动生成，页面仅保留编辑增删与点击搜索。

### 历史检索词补齐与总结导航（2026-10-15）
- `--backfill-keywords` 是显式维护启动参数，日常启动不触发。仅处理 keywords 与 keywordsGeneratedAt 均为空的会议，已有结果（含手动删除后空数组）跳过；写入前重新读取，保留手动词及全部其他字段。
- 使用已配置 LLM 从完整现有总结分段提取，并在本机对照原转写/笔记检查词面。不会重新生成总结；逐场保存及更新全文索引，维护报告在资料库 `keyword-backfill-report.json`。失败保留原数据，重新以该参数启动只处理未完成项。
- 总结章节改为固定顶部按钮，正文锚点使用独立 chapter 前缀避免与导航 ForEach 标识冲突。概览回到标题，原章节标题不变。
- 每条总结直接显示至多三个可试听时间戳及“对照原文”入口；点击后打开左转写、右总结布局，自动定位并高亮依据，提供上一处/下一处切换。笔记引用单独展示，不制造音频时间点。

### 侧栏降噪与面板切换（2026-10-15）
- 后台任务入口仅在处理中、批量待继续/失败、录音待自动补齐时显示；已完成任务不再常驻占位。停止、继续和失败重试能力保留。
- Plaud 同步采用独立 `plaudSyncRunning` 状态，进行中显示按钮状态；结束显示六秒提醒，可查看详情或关闭。最近结果从同步按钮右键菜单查看，侧栏不再长期显示日志。
- 同步期间不显示录音设备状态；问答展开时发言人按钮显示“维护发言人”，点击直接切回维护面板，不会误切成隐藏。
- 问答侧栏宽度调整为 280 点，为较窄窗口留出正文空间。源文对照与问答互斥，避免同时挤出三栏。

### 卡片式会议笔记（2026-10-15）
- `Meeting.noteCards` / `noteDraft` 均为可选 Codable 字段，旧 `notes` 原样保留；草稿每次变更保存，提交后转为卡片。开始输入时捕获音频位置，不在提交时重新取时间。
- 录音时取会议 elapsed，已进入回听时取播放 position；其他情况为无音频位置的会后补充。重点/疑问/待办可一键创建空文字标记。
- NSTextView 输入组件处理回车提交、Shift-回车换行、中文输入法组合状态，以及剪贴板 PNG/TIFF；图片可通过选择或拖入本地 PNG/JPEG/TIFF 添加。
- 图片存放 `Recordings/<meetingID>/Notes/<noteID>.png`，路径相对资料库，可跟随资料库迁移。图片仅本地显示，不送至模型；导出的文字说明图片尚未识别。
- `Meeting.noteText` 合并原笔记与已提交、未删除卡片，供 FTS、总结、问答、关键词依据和 Markdown 使用。草稿和图片路径不进入模型；用户标记不会直接成为已确认决策。
- 卡片编辑保留原时间；删除为软删除，可从“恢复已删笔记”菜单恢复指定卡片，图片随整场会议删除才清理。

### 会议标记交互调整（2026-10-15）

替换上一版卡片与分类工具栏，改为按添加顺序显示的轻量标记流。文字直接编辑；输入框普通回车换行，Command+Return 提交。首次输入锁定录音/播放时间；旗帜按钮与图片记录点击时刻。图片支持本地选择、粘贴及拖入，点击缩略图预览。取消原有笔记保留区；本次正式资料库核查旧笔记与标记均为零，无需历史迁移。底部区域可折叠/展开，高度限制为100/180点，避免挤占转写。

### 阅读优先布局（2026-10-15）

转写使用连续段落，发言人颜色保留，普通段落无卡片底色，仅当前播放/引用句高亮。校对入口悬停或右键显示。发言人侧栏默认关闭，录音时展开会议标记，会后默认收起。已有总结的转写页不显示重新生成入口；总结工具菜单集中模板选择、生成与核对发言人。总结正文不常驻播放器/发言人表单，溯源对照时恢复播放器。章节目录在宽度850点以上放右侧，窄窗口降为章节菜单。检索词默认显示紧凑横排，全部分类按需展开。

### 问答引用改为本地提取（2026-10-15）

模型只返回本次给定的 sourceIDs 和带 ID 的观点；QAEvidence.materialize 校验 ID 属于当前提供的资料，再提取逐字原文。避免多阶段复制摘录产生字词或标点变化后整次回答失败。仍保留引用逐字校验、来源限制、观点审校，不模糊匹配，也不接受未知 ID。复合问题允许回答有证据部分，无法证实的潜台词/动机需明确无法确定。
长会议候选原文超过最终阶段预算时，对所有候选分组复核，逐组保留支撑问题的代表性依据，再合并回答；最多三轮，仍超限明确报错。没有按前N条截断或跳过后半场。

问答单阶段输出若格式或引用编号校验失败，会在同一阶段携带约束自动修正最多两次，避免整场重新读取；仍不接受未知编号或不匹配的引文。最终引用统一从本机原句提取。长会议候选依据超出预算时分组精简，保留来源编号，最多三轮，不能满足预算则明确报错而不静默截断。

### 性能与发布构建（v0.2.0）

无待补齐会议时不创建自动修复定时器；存在任务时才检查到期状态，并读取内存中的会议列表，避免每15秒在主线程解码整库。任务保存后 reload 更新定时器生命周期。录音及播放计时器分别在停止/暂停时撤销；播放计时器允许50ms调度合并。实时配置的钥匙串读取放入后台任务，避免同步进程等待阻塞界面。正式打包使用 Release 优化构建。
