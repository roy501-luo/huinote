# 一键开始会议与录音导航

> 本文保留早期排查过程；后续麦克风采集替换与设备验证见 [麦克风与笔记修复](MICROPHONE_NOTES_VALIDATION.md)。

2026-10-15

## 行为

- 左侧“开始会议”直接创建并启动录音；旁边菜单导入音频/视频。
- 未成功启动采集，不把草稿保存成正式会议。密钥缺失时允许本地录音，明确提示转写缺失。
- 采集成功后启动后台 ASR；启动期间最多缓冲 100 个音频包，断网恢复只发送新音频，不重播旧片段。
- 正在录音的会议和正在浏览的会议独立；实时转写、暂停/继续、结束与会后任务始终归属录音会议。
- 录音期间全局控制条显示状态、时长、暂停/继续、结束和返回录音。可以浏览历史、搜索、问答。
- 录音页优先展开会议标记，自动时间戳；会后按原设置自动处理。
- 麦克风配置变化/无帧时有限重启，最多两次；结束时移除观察者、停止引擎及计时器。设备错误独立展示，不提示成服务配置错误。

## 验证

- 固定证书编译与签名通过；音频、暂停追加、实时稿幂等、弱网重连、全文搜索、持久化和跨会议引用验证通过。
- 新增首包缓冲顺序与断网恢复不重播验证通过。
- 实际 UI：一键开始、暂停、继续、历史会议与问答切换、返回录音、在历史会议页面结束均执行。
- 第一场 95.32 秒：系统声音真实 API 识别测试句；首次发现 AirPods 麦克风无帧，该场不能作为双路成功证据。
- 修复后的第二场 66.58 秒：系统文件 66.02 秒（本场无播放，静音），AirPods 麦克风文件 65.70 秒、24kHz、1,576,800 帧，完整解码；麦克风真实中文转写及会后处理完成，保存 1 条自动时间标记。
- 两次实际录音覆盖系统声音和真实麦克风；不以静音文件冒充有声验证。
- 停止并完成会后任务后两次进程采样 CPU 为 0.3% / 0.0%，RSS 约 267 / 306 MiB；不是长期性能基准。
- 原有 58 场会议 JSON 校验值未改变。测试会议保留，无删除正式数据。

## 设备边界与最终交付

- 后续 40.10 秒测试中，系统通道有声且真实转写成功；麦克风发生采样率/时间线变化，只保存 20.90 秒 + 1.00 秒分段。不能把会后识别完成视为音源完整。
- 新增 `audioCaptureIncomplete` 可选字段，兼容旧数据；会后成功后仍保留“音源有缺失”，未采集到的声音不可恢复。
- 默认 AirPods 后续一次出现无帧；用户授权仅在 App 内做内置麦克风对照，但对照也无帧。尝试强制输入连接后发生 -10875 初始化错误，因此撤回强制设备绑定、输入监听连接和临时测试开关，恢复先前有成功实际录音的路径。
- 最终版保留有限次数引擎恢复、准确音源提示；麦克风间歇性无帧仍待进一步定位，不能宣称彻底修好。
- 调试偏好 `verifyBuiltInMicrophone` 已删除，系统默认输入未修改。最终固定签名构建及自动化回归通过。
- 最后核对原有 58 场会议 JSON 校验值全部一致，本轮新增 5 场测试记录均保留；其中纯静音对照未得到会后识别结果，保留失败事实。
