# 麦克风与会中笔记修复（2026-10-15）

## 修复

- macOS 15 及以上使用 ScreenCaptureKit 的独立麦克风输出，与系统音频分别写入本地 CAF、分别转写；macOS 14 保留 AVAudioEngine。避免原先输入引擎启动成功却间歇性不产帧的问题。框架替换后本机两路实测通过，不将此前现象归因于耳机故障。
- 设置 → 录音可选择 App 使用的输入设备。未连接的指定设备明确报错，不暗中替换。测试后恢复系统默认输入，未修改系统默认设备。
- 中文输入法组合期间不覆盖 NSTextView 内容，提交组合后同步文字；保留无变化刷新时的光标。会议切换重建独立输入框，旧回调不会写入新会议。
- 笔记输入合并 350 ms 后保存，仅更新笔记搜索文档，不逐字重建全部转写索引及加载整个会议库；切换会议、提交、退出时保存待写笔记。
- 粘贴板同时有文字和图片时优先粘贴文字；纯图片仍可插入。

官方 API：[captureMicrophone](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturemicrophone)、[microphoneCaptureDeviceID](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/microphonecapturedeviceid)。

## 自动化验证与边界

- `scripts/verify.sh`：音频 PCM、时间线、ASR 状态、持久化、搜索与笔记局部更新通过。
- `Verification/VerifyNoteEditor.swift`：真实 NSTextView 上模拟输入法 marked text，100 次外部刷新不破坏组合，提交中文、光标保持、清空通过。此项是输入法机制模拟验证，不等同于用户拼音输入法长时间实测。
- 当前环境没有 XCTest 模块，`swift test` 无法执行；独立验证器完成等价关键检查。
- 本轮是真实设备短时回归，不是小时级连续会议或蓝牙断连压力测试；macOS 14 的旧引擎分支未在本机验证。未采到的历史声音不能补回。
