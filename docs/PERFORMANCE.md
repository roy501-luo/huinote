# v0.2.0 性能与能耗检查

2026-10-15，Apple Silicon 开发机。保留现有会议资料，未改动数据库结构。

## 本次优化

- 自动补齐检查仅在存在待补齐会议时运行；无任务时撤销定时器。
- 到期检查使用内存会议列表，取消每 15 秒读取并解码整库的主线程操作。任务保存及重新加载时更新定时器。
- 播放 250ms 更新允许 50ms 调度合并；暂停和结束仍撤销定时器。
- 实时配置的同步钥匙串进程读取移到后台任务，避免阻塞主线程；不承诺消除设备启动时间。
- 安装包使用 Release 优化构建。录音写盘、网络有界队列、笔记 350ms 合并保存和停止时释放采集逻辑保持。

## 实测

同一 11 秒会议详情，未播放、未处理任务；`ps` 每 2 秒采样一次，共 10 次：

| 状态 | CPU 样本均值 | CPU 样本峰值 | RSS 峰值 |
|---|---:|---:|---:|
| 更新前 Debug | 0.56% | 5.6% | 221.5 MiB |
| 更新后 Release | 0.00% | 0.0% | 181.6 MiB |

短录音实际播放到 00:11/00:11，按钮恢复“播放录音”。随后 30 秒采样 CPU 0–0.1%，末段均为0.0%，RSS 降至约150MiB；没有观察到播放结束后持续高占用。

这是短时观察，构建模式、进程缓存和系统内存回收都会影响结果，不能将全部变化归因于单项优化。未测量瓦数、电池续航或长会议压力，不把 CPU 数值等同于耗电量。此次没有新增真实录音或调用云端模型；设备及真实 API 的阶段性证据见其他验证文档。
